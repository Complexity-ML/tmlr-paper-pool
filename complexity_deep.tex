\begin{abstract}
Learned mixture-of-experts routers use contextual hidden states to decide which parameters process each token. We ask how much of that routing signal can come from token identity alone when expert capacity is a small residual over a shared dense MLP. Our model maps each token ID to two narrow experts through a fixed, layer-specific lookup; the experts still transform the same contextual hidden state as the shared branch. In a matched single-seed comparison between 306.5M-parameter models trained on 8B FineWeb-Edu tokens, the token-routed model reaches evaluation-stream NLL 2.9329 versus 2.9482 for the dense baseline at the last common evaluation checkpoint. This stream is drawn from the training split, and the routed implementation is slower. A separate 99.6M-token diagnostic finds a contextual top-2 router with auxiliary load balancing slightly ahead of matched dense and lexical controls. The selected router was subsequently trained for 1.0003B tokens and reaches evaluation-stream NLL 4.8580 on its separate o200k setup; without matched full-budget controls, this promotion run is not a ranking against the historical ablations. Standardized held-out evaluation and replication across seeds remain open.
\end{abstract}

%=============================================================================
\section{Introduction}
\label{sec:introduction}
%=============================================================================

Mixture-of-experts language models usually learn a router from each token's contextual hidden state \citep{shazeer2017outrageously,fedus2022switch,jiang2024mixtral}. The router can adapt expert selection to context, but it also introduces parameters, balancing objectives, and dispatch decisions. Fixed routing provides a useful counterpoint: if a simple token-level signal allocates parameters effectively, some benefits attributed to contextual routing may instead come from stable conditional capacity.

We test this idea in a deliberately asymmetric design. Every token passes through a shared dense SwiGLU MLP. Token identity selects two additional experts, each much narrower than the shared branch, and their output is added as a gated residual. Selection is context independent, but expert computation is not: both the shared branch and the selected experts receive the contextual hidden state produced by the transformer. The experiment therefore asks whether token identity is useful for selecting a residual parameter subspace, not whether lexical lookup can replace contextual computation.

The primary comparison uses two 306.5M-parameter models trained for the same 8B-token budget. The models share their transformer backbone and stored MLP width; one uses a dense width of 4,096, while the other divides that width into a shared width of 3,840 and four routed experts of width 64, with two active per token. At the last common checkpoint of a fixed evaluation stream, the routed model reaches NLL 2.9329 and the dense model 2.9482. The routed model trains more slowly in the current implementation, and the evaluation stream comes from the FineWeb-Edu training split.

This study contributes a controlled observation rather than a general verdict on expert routing. It defines a shared-plus-residual architecture in which token identity controls only expert selection, verifies the realized routing tables and capacity accounting, and reports the full matched-token trajectory. We also report a separate short-budget diagnostic with learned contextual routers and matched dense and lexical controls. It is a promotion test, not a substitute for the 1B-token comparison.

\section{Related Work}
\label{sec:related_work}
%=============================================================================

Learned MoE routers use hidden states to select experts and commonly add an auxiliary objective or another balancing mechanism \citep{shazeer2017outrageously,fedus2022switch,jiang2024mixtral}. These systems test the value of content-adaptive specialization. Our experiment tests a different axis: whether stable token identity is already informative when routing controls only a narrow residual branch.

Hash Layers is the closest precedent \citep{roller2021hash}. It showed that fixed hashes of local token features can compete with learned routing in language models. Our design keeps a dense MLP active for every token and applies fixed top-2 lookup only to a small residual capacity. This makes the routed path a correction to common computation rather than the main feed-forward transformation.

Shared experts also appear in architectures such as DeepSeekMoE \citep{dai2024deepseekmoe}, where they capture computation common to all tokens. Statistical analyses of shared-expert mixtures provide results under explicit estimation assumptions \citep{nguyen2025sharedexperts}. We use the shared-plus-routed decomposition as an architectural prior; our measurements do not test those theoretical guarantees.

\section{COMPLEXITY-DEEP Architecture}
\label{sec:architecture}
%=============================================================================

\subsection{Overview}

The architecture changes only the feed-forward sublayer of a decoder-only transformer. Attention remains standard GQA with 16 query heads, four key/value heads, QK-Norm, RoPE, and causal scaled dot-product attention. Figure~\ref{fig:architecture} isolates the changed computation. For token ID $t$ and contextual hidden state $\mathbf{x}$, the token ID selects residual parameters while both MLP branches transform $\mathbf{x}$.

\begin{figure}[t]
\centering
\includegraphics[width=\textwidth]{architecture_complexity_deep.png}
\caption{Token identity controls only the fixed top-2 lookup. The shared branch and selected residual experts receive the same contextual hidden state.}
\label{fig:architecture}
\end{figure}

\subsection{Fixed token-identity routing}
\label{sec:token_routed_mlp}

Each layer stores a fixed top-2 lookup. The primary expert is a seeded permutation $\pi_l$ of the token-ID residue:
\begin{equation}
r_{l,1}(t)=\pi_l(t \bmod E), \qquad E=4.
\label{eq:routing}
\end{equation}
The secondary table is constructed once, in ascending token-ID order, by selecting the least-used expert other than the primary:
\begin{equation}
r_{l,2}(t)=\operatorname*{arg\,min}_{e\neq r_{l,1}(t)}
\sum_{u=0}^{t-1}\mathbb{1}[r_{l,2}(u)=e],
\label{eq:secondary_routing}
\end{equation}
with lowest-index tie breaking. Because the 32,000-token vocabulary is divisible by four, each expert receives exactly 8,000 primary token IDs. This balances vocabulary cardinality, not corpus traffic.

\subsection{Shared MLP and residual experts}

For contextual hidden state $\mathbf{x}$ and token ID $t$, the feed-forward output is
\begin{equation}
\operatorname{MLP}_l(\mathbf{x},t)=g^s_l\operatorname{Shared}_l(\mathbf{x})+g^r_l\!\sum_{j=1}^{2}0.5\,\operatorname{Expert}_{r_{l,j}(t)}(\mathbf{x}),
\label{eq:mlp_routed}
\end{equation}
where $g^s_l$ and $g^r_l$ are learned scalar gates initialized to $1.0$ and $0.1$. The selected expert outputs use fixed weights $0.5/0.5$. Every branch is a SwiGLU transformation,
\begin{equation}
\text{Expert}_i(\mathbf{x}) = (\text{SiLU}(\mathbf{x}\mathbf{W}^i_{gate}) \odot \mathbf{x}\mathbf{W}^i_{up})\mathbf{W}^i_{down}
\label{eq:expert}
\end{equation}
and the shared branch has the same form with its own parameters. Token identity selects functions, but those functions operate on contextual states. The language-model objective is applied after the complete network; there is no independent expert objective.

\subsection{Capacity and sparse dispatch}

Let $d$ be the model dimension, $d_s$ the shared width, $d_e$ the width of each routed expert, $E$ the number of stored experts, and $k$ the number selected per token. Ignoring biases, the routed MLP stores
\begin{equation}
P_{\mathrm{TR}}=3d(d_s+E d_e)
\end{equation}
parameters per layer and evaluates intermediate width
\begin{equation}
 d_{\mathrm{active}}=d_s+k d_e
\end{equation}
per token. In the evaluated model, $(d_s,E,d_e,k)=(3840,4,64,2)$: stored width is $4096$, matching the dense baseline, and active width is $3968$. The implementation groups tokens by their fixed assignments and evaluates only the selected routed experts. Small expert kernels and dispatch still add runtime overhead, measured in Section~\ref{sec:scaling_300m}.

\subsection{Primary comparison}
\label{sec:config_300m}

We train a token-identity residual model and a dense baseline, both with 306.5M parameters. They use the same 18-layer backbone, tokenizer, 2,048-token context, FineWeb-Edu stream, optimizer, learning-rate schedule, BF16 precision, and 8B-token budget. The global batch is 1,048,576 tokens (eight GPUs, batch 64 per GPU), so equal training steps imply equal tokens seen. The controlled difference is the MLP parameterization in Table~\ref{tab:config_300m}.

\subsection{Optimization}
\label{sec:training_recipe}

Both models use AdamW with $(\beta_1,\beta_2)=(0.9,0.95)$, weight decay $0.1$, gradient clipping at $1.0$, a 5\% warmup, and cosine decay to 10\% of the peak learning rate. Residual output projections use
\begin{equation}
\sigma_{\text{residual}} = \frac{0.02}{\sqrt{2 \times L}}
\end{equation}
for $L$ layers \citep{radford2019language}.

\subsection{Routing and evaluation protocol}
\label{sec:routing_verification}

Checkpoint inspection shows that the primary and secondary lookup buffers in all 18 layers exactly match Equations~\ref{eq:routing}--\ref{eq:secondary_routing}. We therefore identify the realized mechanism from the stored assignments themselves as permuted-modulo primary routing with a cardinality-balanced secondary assignment, rather than inferring it from the historical run label. The fixed evaluation stream is drawn from the FineWeb-Edu training split; it is consistent across the two runs but is not an independent held-out set.

\section{Discussion and Limitations}
\label{sec:discussion}
\label{sec:limitations}
%=============================================================================

The result shows that a fixed token ID can select a useful residual parameter subspace in one matched run pair. It does not show that token IDs encode semantic expert classes. The assignments are modulo partitions up to a layer-specific permutation, and the selected experts transform contextual hidden states. A plausible interpretation is that stable token-conditioned capacity changes which functions are available to recurring lexical items while the shared MLP and attention preserve common contextual processing.

The experiment also does not isolate token identity from every alternative explanation. The 100M ablations in Section~\ref{sec:ablation_100m} include residual, random, and learned contextual controls. The short learned-router panel favors auxiliary balancing, and the selected variant completes its 1B-token promotion run without dead experts. However, both use one seed, a different tokenizer/shard, and different hardware from the historical panel, while the promoted setup has no matched full-budget dense or lexical controls. It therefore validates the promoted run operationally rather than establishing that learned or fixed routing is superior. The historical fixed controls likewise cannot provide a causal ranking of assignment strategies because some nominal controls realize equivalent primary assignments.

The 300M comparison uses one seed per architecture. Its evaluation stream comes from the training split, and standardized downstream or out-of-distribution evaluations are not available for the reported checkpoints. The routed implementation is slower than dense at matched batch. Finally, the stored lookup buffers realize the modulo-primary/cardinality-balanced-secondary rule, not frequency-aware assignment. These limits leave the central observation intact but constrain it to matched-token loss for this run pair.

%=============================================================================
\section{Conclusion}
\label{sec:conclusion}
%=============================================================================

Token identity provides a useful residual routing signal in the reported 306.5M-parameter run pair: after 8B training tokens, the shared-plus-routed model finishes ahead of a matched dense baseline. The observed evaluation-stream NLL gap is $0.0153$; uncertainty is not estimated because each architecture has one seed, and the routed implementation is slower in wall-clock training. The observation poses a concrete question for learned MoE systems: how much contextual routing is necessary when a shared dense path already handles common computation?
