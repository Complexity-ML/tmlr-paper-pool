\section*{Supplementary Methods}

\subsection*{Scope of the control suites}

The reported control experiments are organized into three internally matched panels. All use the same o200k tokenizer family, but absolute losses must not be compared between the historical and contextual implementations because their data ingestion and evaluation streams, hardware and implementation snapshots differ. Panel A is the historical fixed-routing suite on two NVIDIA B200 GPUs. Panel B is a four-condition 99.6-million-token contextual-router diagnostic on two NVIDIA RTX PRO 6000 Blackwell GPUs. Panel C promotes the auxiliary-balanced router to a matched 1.0003-billion-token comparison with dense on the same contextual setup. Every reported row contains one training seed.

Panel A's historical label for a frequency-aware condition was inspected against its realized configuration and checkpoint. No frequency table was populated. The condition therefore implements modulo-primary/cardinality-balanced-secondary routing and is named accordingly here. Likewise, nominal modulo-adjacent and round-robin variants share the same primary assignment in this implementation; their numerical difference is not evidence for a causal difference between primary assignment rules.

Panels B and C use learned contextual routers that score four residual experts from each token's hidden state and select two. Panel B compares auxiliary load balancing, loss-free bias balancing, dense computation and a fixed token-identity control. Panel C promotes only the auxiliary-balanced router. Reported training NLL excludes the auxiliary loss. These controls were not subjected to the four-task downstream panel; no downstream-performance claim is made for them.

\subsection*{Metric selection}

For the primary comparison, the manuscript reports point measurements at matched token counts and the last common evaluation step. It does not use the historical mean over the last 50 logged training steps. Evaluation-stream NLL is separated from training NLL in every table. Because the stream was sampled from the training split, it is not described as validation or held-out loss.

The 1-billion-token controls have a 954-step budget, log training metrics every ten steps and evaluate every 750 steps. Step 950 is therefore the last common logged training point and step 750 the last common evaluation checkpoint; the table does not substitute one quantity for the other. The short diagnostic ends at step 95, logs training metrics every five steps and evaluates every 75 steps, yielding the analogous step-95/step-75 pair.

Multiple-choice results use length-normalized accuracy. Standard errors are those returned by LM Evaluation Harness. WikiText-2 word perplexity is reported without a harness-provided standard error. No post-hoc benchmark selection or sample truncation was used.

\section*{Reproducibility checklist}

The anonymized source package contains:
\begin{itemize}
  \item the primary and control model implementations;
  \item realized JSON run configurations and raw CSV metrics;
  \item the exact 32,000-entry tokenizer used by the primary checkpoints;
  \item the o200k shard-preparation script and control configurations;
  \item unit tests for route construction, expert selection and capacity accounting;
  \item scripts that regenerate the manuscript figures and aggregate tables; and
  \item downstream aggregate results with package versions and evaluation seeds.
\end{itemize}

Large checkpoints and per-example benchmark logs are excluded from the compact manuscript archive but are available to editors and reviewers. The technical artifact manifest supplied with the code records checkpoint provenance; these implementation details are intentionally omitted from the paper itself.
